## 补跑顺序

1. **P0，先补配置及已有文件导出，无需新跑：** 100k 模型/归一化器哈希、实际 prior/likelihood 配置、采样器设置、初值/续跑来源、checkpoint 及随机状态。索取 65k 16,018 步完整链与分段顺序，独立保留为模型版本比较；不与 100k 链混合。
2. **P0，延长现有 100k 8D ensemble：** 同一目标和配置续跑，保存完整有序样本、log_prob、checkpoint。建议每增加 2,000 步检查一次；这是检查节奏，不是保证足够的总长度。优先检查所有八个参数及 KP/MS 尾部、相关时间和区间端点的变化。
3. **P0，补独立初值 100k 8D ensemble：** 目标为四组独立运行（现有链身份确认后计入一组，新增三组），各 32 walkers，分别覆盖先验内分散的有效初值，不能复制同一 checkpoint 冒充独立初始化。先各跑 3,000–5,000 步作诊断检查，再按稳定性延长；不预设这些步数即收敛。
4. **验收后再汇总：** 确认各运行得到一致的一维/二维边缘分布；使用适用于独立 ensemble 的跨运行比较及 Monte Carlo 误差估计，检查有效样本量、自相关时间和 2.5%/97.5% 分位数误差。emcee 文档中约 50 倍相关时间是长度检查参考，不是唯一停止条件。最终选择 burn-in 后重算区间。
5. **P1，只有需要拆解观测贡献时再跑：** 同一 100k 模型的 LF-only、LF+tau、LF+tau+xHI 8D 对照。当前主结果是联合约束，不要求先增加固定 KP/MS 的 6D 链，也不需要为 KP 的边缘分布增加固定 KP 的 7D 链。

本次未启动任何 MCMC、训练或集群任务。更长链用于提高采样精度；其本身不会增加观测信息，也不能预先认定必须加入某一种观测才能获得约束。

## 复现与产物

运行 `/usr/bin/python3 paper/analysis_kpms_20261106/analyze.py`，再运行同目录 `build_page.py`。原始 HDF5 和上游 README 保持不变。

- `analysis.json`：文件哈希、先验来源、全部选样区间、诊断定义及二维概率积分检查。
- `intervals.csv`：全链、不同舍弃量及前半段的完整区间。
- `kp_ms_marginal_prior.png`：蓝色边缘分布与橙色虚线先验，二维单层灰填色/蓝轮廓。
- `kp_ms_stability.png`：walker 时间轨迹、逐步中位数及前后半段分布。
- `index.html`：离线展示与数据下载。
