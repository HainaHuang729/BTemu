# PS emulator plan (21cmEMUv3-style) — 2026-11-02

Goal: emulate 21cm summary observables for the BT model, following 21cmEMUv3 but staying inside our CPU-only budget where possible. Target outputs: cylindrical PS (32 k_perp x 64 k_par, z=5-30), spherical PS, mean xHI(z), mean Ts(z), global dTb(z), UV LF, tau.

## 1. What the reference does (verified from arXiv:2606.00219v1)

- Inputs: 11 parameters (7 ACG + 3 MCG + sigma_8) plus redshift z as an extra input for the cylindrical PS; all outputs are **summaries**, not 3D lightcones ("rather than emulating full 3D lightcones, we emulate only lower-dimensional summary statistics").
- Cylindrical PS: score-based diffusion (32 x 64 bins), trained as the **mean** PS over realizations.
- Other six summaries: LSTM over the redshift axis (xHI(z), Ts(z), dTb(z), spherical PS(z), LF(z), tau).
- Training database: tens of thousands of 21cmFAST runs with independent initial conditions; storage is summary-level, not lightcone-level.

## 2. Proposed plan for us

### 2.1 Data (CPU only, same pipeline as now)

| item | choice | cost |
|---|---|---|
| design | Sobol over 10-11 params, one unique IC per point | -- |
| per realization | 250 Mpc / 512^3, 31 z nodes, 16 cores, ~416 s | 1.85 core-h |
| target N (staged) | 10,000 -> 25,000 -> 47,000 | 18.5k / 46k / 87k core-h |
| wall time at ~1000 cores | -- | 0.8 / 1.9 / 3.6 days |
| storage | cylindrical PS per z: 32x64x21 x4 B = 172 kB; 47k -> ~8 GB (plus summaries ~1 GB) | negligible |
| do NOT store | full lightcones (9.4 GB each -> 440 TB) | -- |

Note: the current xHI-history production (100k points) already contains the same runs; PS extraction from the stored boxes is **not** possible because boxes were not kept, so PS requires re-running (or a hybrid: recompute PS for a subsample of the 65k validation points).

### 2.2 Networks

| branch | model | hardware | training time |
|---|---|---|---|
| cylindrical PS | score-based diffusion (DDPM/DDIM) on 32x64 maps conditioned on params + z | 1x GTX1080Ti (11 GB) | 3-7 days single GPU; ~1 day on 4-8 GPUs |
| spherical PS, xHI(z), Ts(z), dTb(z), LF, tau | LSTM (or our ResMLP as a cheaper alternative) | CPU | 10-30 h per output family |
| fallback (no GPU) | deterministic CNN/ResMLP on the same PS maps (mean only) | CPU | 20-50 h |

Inference cost: diffusion sampling ~0.1-1 s per parameter point (DDIM); an MCMC with 32 walkers x 2000 steps would need 6,400-64,000 s, so production inference should use the deterministic CNN head or few-step sampling.

### 2.3 Validation

- Holding out 10% of the database; report per-(k_perp,k_par) fractional error and per-z curve.
- IC-averaging: with one unique IC per point the regression learns the mean; report the residual IC scatter separately.
- Downstream: compare posterior from PS-only vs PS+tau+xHI, as in T3.

## 3. Total time (staged)

| stage | content | wall time |
|---|---|---|
| A | 10k realizations + PS extraction | ~1 day (uses current CPU capacity after the 100k run) |
| B | LSTM/ResMLP on six summaries (10k) | 1-2 days CPU |
| C | deterministic CNN on cylindrical PS (10k) | 1-2 days CPU |
| D | diffusion upgrade (if GPU granted) | 3-7 days GPU for training |
| E | validation + inference comparison | 2-3 days |
| **total (no GPU)** | A+B+C+E | **~1.5-2 weeks** |
| **total (with GPU diffusion)** | A+B+D+E | **~2-3 weeks**, dominated by GPU training |

Full v3-scale database (47k) adds ~3 days of CPU time (A) and roughly doubles the training time.

## 4. Dependencies and risks

- GPU access: our account is excluded from several `chpc-gpu*` nodes; `chpc-gpu001` (8x GTX1080Ti) is in the general `chpc` partition and may be usable, subject to quota.
- IC noise on PS is larger than for xHI histories; a deterministic mean-PS emulator may hit the same noise floor problem, which is exactly why v3 used diffusion for the mean PS.
- Storage policy: summaries only, never lightcones.
- The BT (kp, ms) extension: the same two extra inputs enter as conditioning; no change to the pipeline.
